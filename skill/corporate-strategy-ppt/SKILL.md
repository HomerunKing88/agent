# 경영진 1page 보고서 PPT 제작 (코드 기반)

**SKILL_VERSION: v7 (2026-08-20)**

### 0. 버전 확인 (작업 시작 전 1초)

`SKILL_VERSION`이 v7보다 낮으면 이 스킬은 구버전으로 되돌아간 상태다.
`/mnt/skills/user/`는 세션마다 새로 만들어지는 컨테이너 로컬 디스크이고
영속 저장소가 아니므로, 과거 대화에서 이 폴더를 직접 수정한 내용은 남아 있지 않다.
구버전이면 사용자에게 그 사실을 먼저 알리고, 이번 세션에서 고친 내용은
반드시 아래 5.5단계(재패키징)로 되돌려 준다.

**이 폴더를 직접 편집하는 것은 스킬 업데이트가 아니다.**
편집 후 반드시 `.skill`로 패키징해 사용자에게 전달하고 설치까지 확인해야 반영된다.

pptxgenjs로 A4 가로 보고 장표를 생성하고, LibreOffice 렌더링 + 좌표/픽셀 검증으로
품질을 보증하는 워크플로우. 차트는 네이티브 차트 대신 **도형(rect)으로 직접 그린다**
(라벨 색·위치 완전 제어, PPT에서 개별 도형으로 편집 가능).

- `references/qa-checklist.md` — 검증 파이프라인 명령어와 임계값. **산출 전 반드시 수행한다.**

- `assets/formal_template.pptx` — 공식 양식 원본(로고·사진·레이아웃 포함). 복사해서 편집.

## 워크플로우

### 1. 수치 확정이 먼저

- 엑셀 원천을 openpyxl로 읽고 **모든 파생 수치를 파이썬으로 재계산**해 출력·검증한다.
  파일의 표시값을 눈으로 옮기지 않는다.
- 표시 반올림을 먼저 확정한다. 장표 내 산술은 **표시값 기준으로 맞아야 한다**
  (예: 36.9 → 42.9는 +6.0%p로 표기, 소수 셋째 자리 기준 5.95라도 표시 정합 우선).
- 차이·평균 열은 표시값끼리 계산한다. 음수는 **마이너스 부호(-)** 로 표기한다(△ 금지, 빨강 금지).

### 2. 페이지 설계

기본 구조(위에서 아래로): 제목(HY헤드라인M 17pt bold, 우측 표기·구분선 없음) →
딥블루 배너 15pt bold **중앙정렬**(흰색 사실 + 앰버 결론, 보조수치 11pt 괄호) →
섹션 칩(HY헤드라인M 12pt, bold 없음 + 10pt 보조설명) 아래 표·차트·불릿 직접 배치 →
**크림 박스(FFF2CC)에 검정 일반 글씨로 페이지 결론** → 8pt 각주(하단 라인 없음, 바닥 기준 배치).
**본문 텍스트 10pt 미만 금지**(각주 8pt·표 9pt·차트 라벨 9pt 예외).
완성 모범 사례 `assets/reference_example.pptx`를 렌더해 참고한다.
상세 문법과 좌표 예산은 design-system.md 참조.

'26.8 확정 사항(사용자 재수정으로 반복 확인된 것 — 처음부터 이렇게 만든다):
1. **폰트 이원화**: 제목·배너는 HY헤드라인M + bold, 섹션 칩은 HY헤드라인M bold 없음, 나머지 전부 맑은 고딕
2. **표는 전 셀 중앙정렬**. 좌측정렬은 셀 안에서 줄바꿈되는 긴 서술문 열에만, 그 열도 헤더는 중앙
3. **표 rowH는 1줄 0.33 / 2줄 0.58 이상**. 더 작게 주면 PowerPoint가 늘려 아래 요소와 겹친다
4. **⇒ 결론 줄에는 ▸ 마커를 붙이지 않는다**
5. **각주는 바닥 기준**: `y = 7.70 - 0.14 × 줄수`. 페이지마다 y를 다르게 두지 않는다
6. **페이지 결론은 크림 박스**. 배너와 같은 네이비 박스를 하단에 또 깔지 않는다
7. **줄글만 있는 블록 뒤에는 옅은 회색 패널(F7F8FA)** 을 깔고, 상하 여백을 균등하게 잡는다
8. **여백을 남기지 않는다**: 빈 공간이 생기면 정보를 더하지 말고 행 높이·간격·도형 크기를 키워 채운다

### 3. 생성 스크립트 작성

- `scripts/template.js`를 작업 폴더로 복사하고 require해서 사용한다.
- **수정은 항상 생성 스크립트를 패치 후 재생성**한다. 산출된 pptx를 직접 고치지 않는다
  (단, 사용자가 편집한 기존 파일의 일부 페이지만 바꿀 때는 4번 방식).
- 표는 `colW 배열의 합계 == w`를 반드시 맞춘다. 불일치하면 표가 지정 폭을 넘어
  옆 요소와 겹친다(실제 사고 사례).
- 텍스트 줄 수 예산: 한글 기준 줄당 글자 수 ≈ `w(인치) × 7.4 ÷ (fontSize/10)`.
  각주(8pt)는 총 4행 이내로 계획한다.

### 4. 기존 파일의 페이지 보존 병합

사용자가 편집한 파일에서 특정 페이지만 교체할 때:

```python
# 새로 생성한 1페이지의 도형을 기존 파일 slide N에 이식 (다른 페이지는 바이트 보존)
SHAPE_TAGS = ('}sp','}pic','}graphicFrame','}grpSp','}cxnSp')
for el in list(dst_slide.shapes._spTree):
    if el.tag.endswith(SHAPE_TAGS): dst_slide.shapes._spTree.remove(el)
nid = 100
for el in src_slide.shapes._spTree:
    if el.tag.endswith(SHAPE_TAGS):
        cp = copy.deepcopy(el)
        for c in cp.iter():
            if c.tag.endswith('}cNvPr'): c.set('id', str(nid)); nid += 1
        dst_slide.shapes._spTree.append(cp)
```

수치만 갱신할 때는 python-pptx로 **런 단위 문자열 치환**(긴 문구 먼저, 겹치는 짧은
숫자는 나중에; 유지해야 할 동일 숫자가 있으면 치환 목록에서 제외)한 뒤
**구수치 잔존 스캔**으로 이전 숫자가 한 곳도 남지 않았음을 확인한다.

python-pptx로 런을 새로 만들 때는 **글자색을 반드시 명시**한다(RGBColor(0,0,0) 등).
색을 생략하면 도형 기본색(밝은 색)을 상속받아 글자가 배경에 묻히는 사고가 난다.

### 5. QA 파이프라인 (생략 금지)

`references/qa-checklist.md`의 전체 절차 수행: validate → PDF 변환 → 150dpi 렌더 →
view로 전체·크롭 시각 검사 → pdftotext -bbox 좌표 검증 → 필요시 PIL 픽셀 검증.
사용자에게 전달하기 전에 발견한 문제는 스크립트를 고쳐 재생성하고 다시 전체 검증한다.

## 하지 말 것

- pptxgenjs 네이티브 addChart 사용(스타일 제어 불가, 라벨 색 일괄 적용 문제). 도형으로 그린다.
- 본문 10pt 미만 글씨(콘텐츠가 빈약해 보임). 헤더 우측 본부명·날짜 표기.
- 아이콘 크기·모양 혼용, 행 내 비정렬. 도형(체브론 등) 안 한글의 글자 단위 파단
  ("적립/금" 불가 — 넓은 오버레이 텍스트 박스로 단어 줄바꿈 보장).
- 표 줄무늬·조건부 음영 남발. 기본은 흰 바탕 + 당사 열 하늘색 + 강조 행 볼드.
- 대구식 수사("단순 A가 아니라 B", "A를 넘어 B")와 붙임표(—) 삽입구. 결론은 단정 평서문.
- 표 본문을 짧은 구절인데 좌측정렬하기(열 경계가 어긋나 보인다).
- 한 열의 모든 셀을 bold 처리하기(전부 굵으면 강조가 사라진다). 강조는 열 하나·행 하나로 제한.
- 스탯 카드 여러 개 중 하나만 네이비 반전하기. 값의 증감을 보여줄 때는 배경을 반전하지 말고
  **숫자 색을 navy → title → gray로 단계화**하고 기준 카드에만 옅은 배경(tint)을 깐다.
- 조직·본부를 나란히 보여주는 표에서 한쪽 행만 글자색을 다르게 하기(차등 근거가 없으면 통일).
- 검증 없이 전달. 렌더 이미지를 실제로 열어 보지 않은 산출물은 미완성이다.
