# shin-ppt1 — 테마 전환형 1page 보고서 PPT

**SKILL_VERSION: v14 (2026-08-27)**

### 0. 버전 확인 (작업 시작 전 1초)

`/mnt/skills/user/`는 세션마다 새로 만들어지는 컨테이너 로컬 디스크다. 과거 대화에서 이
폴더를 직접 고친 내용은 남아 있지 않다. **이 폴더를 직접 편집하는 것은 스킬 업데이트가
아니다.** 편집 후 `.skill`로 패키징해 전달하고 설치까지 확인해야 반영된다(6단계).

## shin-ppt와의 관계

골격·도식·아이콘·문안 규칙은 shin-ppt v4와 같다. 다른 것은 **색을 다루는 방식 하나**다.

| | shin-ppt v4 | shin-ppt1 |
|---|---|---|
| 팔레트 | 차콜+틸 고정 1종 | 테마 4종에서 선택 |
| 색 참조 | 호출부에서 `C.accent` 등 직접 | 동일. 단 `useTheme()`이 값을 갈아끼움 |
| 지면색 | 흰색 고정 | 흰색 또는 크림(paper) |
| 숫자 열 | 맑은 고딕 중앙정렬 | 동일. 1행·1열 중앙정렬을 검사기가 강제 |
| 막대 | 단일 계열 | 단일 + 다계열(`barsGroup`, 계열색 순서 고정) |

색 지정이 전혀 없는 요청이면 shin-ppt를 쓴다. 이 스킬은 **톤을 고르는 판단이 필요할 때**
쓴다.

## 이 스타일이 존재하는 이유

작성 주체가 특정 부서로 읽히지 않아야 하는 보고에 쓴다. 구조는 선·여백·타이포 위계로
만들고, 색면은 상단 요약박스 하나로 제한한다. 테마를 4종으로 나눈 것은 개성을 내려는
것이 아니라 **보고 성격이 다르기 때문**이다. 대외 심의 자료와 회장 인쇄 보고와
다계열 수치 페이지는 같은 팔레트로 셋 다 잘 나오지 않는다.

## 필수 참고 파일

- `references/anti-slop.md` — 장표가 AI가 만든 티가 나는 지점 목록. **산출 전 자체 점검.**

- `scripts/template.js` — 헬퍼 모듈. 작업 폴더에 복사해서 require한다.
- `scripts/build.sh` — **생성·검증·산출 일괄 실행. 이걸로만 만든다.**

  (타임라인+매트릭스 / 워터폴+추이 / 수익구성 누적막대+구성비표 / 단계띠+간트 /
  프로세스+평가격자 / 분기구조+깔때기). 페이지 표기는 각주 줄 오른쪽에 있다.
  새 장표 제작 전 렌더해서 밀도와 글씨 크기를 눈으로 맞춘다.

## 워크플로우

### 1. 테마를 먼저 정한다

수치를 뽑기 전에 정한다. 나중에 바꾸면 페이지 밀도가 어긋난다.

| 상황 | 테마 |
|---|---|
| 상급자 개인 보고, 타 본부장 보고. 기본값 | `report` |
| 대외 제출, 심의·감사 자료 | `mono` |
| 인쇄해서 손에 들고 보는 회장·이사회 보고 | `paper` |
| 계열이 셋 이상인 수치 페이지 | `dense` |
| 회의실 스크린 투사 | `report` 또는 `mono` |

**한 덱 안에서 테마를 섞지 않는다.** 두 판본이 필요하면 같은 생성 스크립트를 테마만
바꿔 두 번 돌린다. 기준본이 테마를 섞은 것은 견본이기 때문이고, 실제 보고서에서는 하지 않는다.

네 테마 모두 밝은 지면이다. 어두운 지면 테마는 두지 않는다. A4로 뽑으면 배경이 통째로
찍히고, 보고 자료는 결국 인쇄된다. 스크린 투사도 흰 지면으로 한다.

### 2. 수치 확정

- 파생 수치는 전부 코드로 재계산해 출력·검증한다. 표시값을 눈으로 옮기지 않는다.
- 표시 반올림을 먼저 확정하고 **장표 내 산술은 표시값 기준으로 맞춘다.**
  합계가 구성 항목 합과 다르면 읽는 사람이 먼저 발견한다.
- 음수는 마이너스 부호(-)로 표기한다. △ 기호와 빨강 강조는 쓰지 않는다.
- **글꼴은 두 벌뿐이다.** 페이지 제목과 상단 요약박스가 HY헤드라인M, 나머지 전부가
  맑은 고딕이다. 등폭 글꼴은 쓰지 않는다(`tnum` 옵션은 오류를 낸다).
- **표의 1행과 1열은 중앙정렬이 기본이다.** 숫자 열·짧은 값 열도 중앙정렬이고,
  셀 안에서 줄바꿈되는 긴 서술문 열만 `tdL`로 좌측정렬한다.
  자릿수가 세 자리 이상 벌어지는 표에 한해 `numAlign: "right"`를 연다.

### 3. 페이지 설계 — 순서를 지킨다

2단을 먼저 긋고 내용을 부어 넣으면 한쪽이 남거나 모자라고, 칸을 채우려고 항목을 늘리게
된다. 그 결과물은 사람이 만든 자료로 읽히지 않는다.

1. 이 페이지에서 **판단 근거가 되는 블록 하나**를 정하고 그것부터 크게 배치한다
2. 나머지를 남는 자리에 맞춘다. 2단이 필요하면 그때 **비대칭**으로 자른다(표는 좁게, 문장은 넓게)
3. **병렬 항목은 세 개를 넘기지 않는다.** 넷 이상이면 표로 옮기거나 묶는다
4. 항목의 해석은 별도 불릿으로 빼지 말고 **표 안 열로 넣는다**
5. 남는 세로 공간은 **행 높이와 블록 간격으로 흡수**한다. 항목을 추가해 채우지 않는다
6. **도형 크기는 담는 정보량에 맞춘다.** 숫자 네 개를 지면 절반짜리 색면으로 키우지 않는다.
   크게 그릴 값이 있는 것만 크게 그리고, 남는 자리는 표나 문장으로 채운다

여백은 숫자로 맞춘다. 콘텐츠 시작 2.00, 소제목→콘텐츠 0.44, 블록 간격 0.34,
2단 좌우 하단 차이 0.40 이내, 하한은 각주 1줄 7.79 / 2줄 7.64이다. 페이지를 다 짠 뒤
`tpl.checkLayout()`을 부르면 하한 초과·좌우 어긋남·잔여 여백을 빌드 중에 잡아 준다.
전체 표는 `references/design-system.md` 5절에 있다.

골격은 (눈썹 라벨) → 제목 → 굵은 마감선 → **상단 요약박스(두괄식)** → 소제목(세로바) →
콘텐츠 → (필요할 때만) 메시지 박스 → 각주(바닥 기준).

**제목 오른쪽은 비워 둔다.** 기준일·출처·페이지·작성부서는 전부 각주 줄로 내린다.
페이지는 `footer(s, notes, { page: "3 / 10" })`로 각주 줄 오른쪽 끝에 붙인다.
단위 표기는 소제목 옆 보조 설명 자리다.

**하고 싶은 말은 상단 요약박스에 두괄식으로 넣는다.** 하단 시사점 행을 매 페이지에
붙이지 않는다. 본문 중 꼭 짚어야 할 메시지가 있을 때만 `msgBox`를 페이지당 한 개 쓴다.

### 4. 글씨 크기 — 블록에 눌리지 않게

**크기는 `tpl.TS`에서만 가져온다.** 생성 스크립트에 `fontSize: 11` 같은 숫자를 쓰지 않는다.

기본값은 표 본문 12.5pt(`TS.table`), 불릿 12pt(`TS.bullet`), 소제목 13.5pt(`TS.sub`)다.
열이 좁아 줄바꿈이 나면 11.5pt(`TS.tableMin`)까지 내리고 그 아래로는 내리지 않는다.
각주(9pt)를 빼면 어떤 글씨도 10pt 아래로 가지 않는다.

표 행 높이는 `글씨(pt) ÷ 24 + 0.20` 이상이다. 12.5pt면 0.72다.

"작아 보인다"는 지적의 실제 원인은 절대 크기가 아니라 글씨와 블록의 비율이다.
표나 도식을 키워놓고 글씨를 그대로 두면 안이 비어 보인다. **블록을 키웠으면 글씨도 같이
키우고, 글씨를 못 키우겠으면 블록을 키우지 않는다.** 전체 스케일 표는
`references/design-system.md` 3절에 있다.

### 5. 구조 설명 페이지는 도식으로

구조·순서·계층·수치·일정은 표로만 쓰면 관계와 방향이 보이지 않는다. 도식 15종을 목적에 맞게 고른다.

**구조·관계**

| 설명하려는 것 | 헬퍼 |
|---|---|
| 순서·공정, 자본이 돌아오는 흐름 | `flow` (회귀 경로 옵션) |
| 계층·자본구조(선순위/메자닌/에쿼티) | `stack` |
| 하나의 값이 여러 갈래로 나뉘는 구조 | `branch` |
| 상위 1개 아래 하위 n개의 조직·구성 | `tree` |
| 부서가 여럿인 절차. 누가 무엇을 하는지 | `swimlane` |
| 단계별로 줄어드는 구조(파이프라인·심사 통과) | `funnel` |

**판단·비교**

| 설명하려는 것 | 헬퍼 |
|---|---|
| 두 축으로 갈리는 포지셔닝·우선순위 판단 | `matrix` (2×2) |
| 두 방식을 항목별로 맞대는 비교 | `compare` |
| 대안 × 평가항목 격자. 신호등 대신 농도 3단계 | `heat` |

**수치**

| 설명하려는 것 | 헬퍼 |
|---|---|
| 항목별 크기 비교 | `bars`(단일) / `barsGroup`(다계열) |
| 수치가 왜 얼마나 움직였는지 분해 | `waterfall` |
| 시계열 방향. 막대로는 추세가 안 보일 때 | `lineTrend` |
| 구성비. 총액 변화가 중요하면 금액 누적 막대 | `chartBar` + `barGrouping: "stacked"` |
| 구성비. 총액이 무의미하거나 이미 밝혔으면 100% 누적 | `chartStack100` |

**일정**

| 설명하려는 것 | 헬퍼 |
|---|---|
| 시점과 마일스톤 | `timeline` |
| 기간이 겹치는 과제 | `gantt` |
| 단계 이름만 이어 붙인 로드맵 | `chevron` |

고를 때 헷갈리는 세 쌍이 있다. `timeline`은 시점을 찍고 `gantt`는 기간을 그린다.
`bars`는 크기를 비교하고 `lineTrend`는 방향을 보여준다. `flow`는 순서를 보여주고
`swimlane`은 순서에 더해 주체를 보여준다.

**같은 페이지에 도식을 셋 이상 넣지 않는다.**

### 5-1. 수치는 네이티브 차트·표로 넣는다

받는 사람이 숫자를 고칠 수 있어야 한다. 도형과 텍스트 상자로 그린 막대는 숫자를 바꾸면
막대 길이가 따라오지 않고, 셀을 추가할 수도 없다.

| 넣는 것 | 방식 | 결과 |
|---|---|---|
| 표 | `openTable` → `addTable` | 파워포인트 네이티브 표. 셀 수정·행 추가 가능 |
| 평가 격자 | `heat` → `addTable` | 셀 채우기로 농도 표현. 글자·색 직접 수정 가능 |
| 세로 막대 | `chartBar` | 네이티브 차트 + 엑셀 워크시트 임베드 |
| 꺾은선 | `chartLine` | 〃 |
| 100% 가로 누적 | `chartStack100` | 〃 (워크시트에는 구성비 %가 담김) |
| 증감 분해 | `chartWaterfall` | 〃 (첫 계열 "받침"이 막대를 띄우는 값) |

차트를 더블클릭하면 "데이터 편집"이 열리고, 숫자를 고치면 막대가 따라 바뀐다.

도형 기반 `bars` `barsGroup` `lineTrend` `stackedBar` `waterfall`도 남겨 두었다.
숫자가 확정돼 다시 고칠 일이 없고, 라벨 위치를 정밀하게 잡아야 할 때만 쓴다.
**기본은 네이티브 차트다.**

구조 도식(`flow` `stack` `branch` `tree` `matrix` `timeline` `compare` `chevron`
`swimlane` `funnel` `gantt`)은 숫자가 아니라 관계를 그리므로 도형으로 둔다.

차트에서 알아둘 것

- 누적 막대에서 데이터 라벨 위치는 `ctr`만 된다. `outEnd`를 쓰면 파워포인트가 거부한다
- `chartWaterfall`은 라벨을 끄고 값축을 켠다. 받침 계열 값까지 찍히기 때문이다.
  막대마다 값을 찍어야 하면 도형 기반 `waterfall`을 쓰고 원 수치를 같은 페이지 표에 남긴다
- `chartStack100`은 적은 순서대로 위에서 아래로 보이도록 내부에서 행을 뒤집는다
- 차트 안 글씨는 렌더 시 한 단계 작아 보이므로 `chartBase()`가 본문보다 한 칸 올려 잡는다 아이콘은 폰트 글리프가 아니라 도형으로 그린
10종을 쓰고, **단독으로 나열하지 않는다.** 도식 카드 안이나 테두리 있는 블록 안에서만 쓴다.

### 6. 생성과 검증 — `build.sh` 한 줄로 끝낸다

```bash
./build.sh <생성스크립트>.js <산출파일명>.pptx
```

**절차를 손으로 나눠 밟지 않는다.** 단계를 하나 빠뜨리는 순간 그대로 통과하고,
그게 지금까지 오류가 반복된 이유다. `build.sh`가 다섯 단계를 순서대로 돌리고
**어느 하나라도 걸리면 산출 폴더에 파일을 내보내지 않는다.**

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| 0 | pptxgenjs 확인·설치 | 설치 시도 후 중단 |
| 1 | 생성. `tpl.save()`가 레이아웃 위반을 막는다 | 파일 자체가 안 생김 |
| 2 | `preflight.py --fix` 구조 검사 20가지 | 중단 |
| 3 | PDF·PNG 렌더 | 중단(파일이 깨진 것) |
| 4 | 텍스트 최하단 ≤ 593pt | 중단 |
| 5 | `/mnt/user-data/outputs`로 복사 | — |

렌더 이미지는 `build_render/pg-*.jpg`에 남는다. **이건 눈으로 확인한다.**
문안, 수치 해석, 밀도는 구조 검사가 못 잡는다.

### 6-1. 생성 스크립트를 쓸 때 지킬 것

- **작업 폴더에서 `npm install pptxgenjs`를 먼저 돌린다.** 컨테이너는 세션마다 새로 뜨므로
  지난 세션에 설치했더라도 다시 해야 한다. `build.sh`가 없으면 알아서 깐다.
  (`preflight.py`는 파이썬 표준 라이브러리만 쓴다.)
- `scripts/`의 `template.js` · `preflight.py` · `build.sh`를 작업 폴더로 복사한다.
- `tpl.newPres(pptxgen, 테마, 모서리)`로 시작한다. 모서리 기본은 `soft`이고
  대외·심의는 `square`, 화면 배포는 `round`다. **덱 단위로 한 번만 정한다.**
- 슬라이드는 `tpl.addSlide(pres)`로 만든다. `pres.addSlide()`를 직접 쓰면
  paper 테마에서 지면색이 안 깔린다.
- **마지막 줄은 `tpl.save(pres, process.argv[2]);` 로 쓴다.** `build.sh`가 산출 경로를
  첫 인자로 넘긴다. 파일명을 스크립트 안에 박으면 build.sh가 넘긴 이름과 어긋난다.
  `pres.writeFile()`을 직접 부르면 레이아웃 관문을 우회하게 된다.
- 페이지를 다 짠 뒤 `tpl.checkLayout()`을 부른다. 여기서 나온 위반이 저장을 막는다.
- 표 스타일은 `tpl.makeTableStyles()`로 호출 시점에 만든다. 테마 전환 이후여야 그 테마 색이 들어간다.
- 표는 `colW 합계 == w`를 맞춘다.
- **색과 글씨 크기를 직접 쓰지 않는다.** `C.*`와 `TS.*` 키로만 참조한다.
- **수정은 생성 스크립트를 고쳐 다시 돌린다.** 산출된 pptx를 직접 손대지 않는다.
  손댄 수정은 다음 실행에서 사라지고, 그 파일은 preflight를 다시 통과한 적이 없다.
- 산출 전 `references/anti-slop.md`의 자체 점검 5항목을 본다.

### 7. 스킬을 고쳤다면: 재패키징 (생략 시 다음 세션에 전부 사라짐)

```bash
cp -r /mnt/skills/user/shin-ppt1 /tmp/          # 폴더명 그대로 유지
# /tmp/shin-ppt1 에서 편집 + SKILL_VERSION 올리기
cd /tmp && python3 -c "import sys; sys.path.insert(0,'/mnt/skills/examples/skill-creator'); \
  from scripts.package_skill import package_skill; package_skill('/tmp/shin-ppt1')"
cp /tmp/shin-ppt1.skill /mnt/user-data/outputs/
```

`present_files`로 `.skill`을 전달하면서, 파일 카드의 **Save skill** 버튼을 눌러야
설치가 완료된다는 점을 한 문장으로 안내한다.

## 하지 말 것

- 색 값이나 글씨 크기를 생성 스크립트에 직접 쓰기. `C.*`와 `TS.*` 키로만 참조한다.
- 블록만 키우고 글씨는 그대로 두기. 셀 안이 비어 보이고 그게 작아 보인다는 인상을 만든다.
- 보라·자주 계열, 형광·고채도 색 쓰기. 금융권 보고서 색이 아니다.
- 초록·빨강을 증감 신호로 쓰기. 계열색으로만 쓰고 증감은 마이너스 부호로 표기한다.
- `checkLayout()` 없이 페이지 마무리하기. 여백은 눈으로 맞추지 않는다.
- 한 덱에서 테마 섞기. 인쇄물에서 낱장이 섞여 들어간 것처럼 보인다.
- 어두운 지면 테마를 새로 만들어 쓰기. 인쇄가 안 된다.
- 계열색 순서를 페이지마다 바꾸기. 같은 계열은 자료 전체에서 같은 색이다.
- 막대 계열을 여섯 개 넘기기. 넘으면 표로 옮긴다. `mono`에서는 네 개가 상한이다.
- 하우스 스타일의 딥블루 배너·라운드 칩·괘선 표·하단 크림박스 문법을 가져오기.
- 매 페이지 하단에 시사점 행 넣기. 결론은 상단 요약박스에서 한 번만.
- 표 본문을 11.5pt 아래로 내리기. 좁으면 열 구성을 바꾸지 글씨를 줄이지 않는다.
- 셋째 글꼴 들이기. 제목·요약은 HY헤드라인M, 나머지는 맑은 고딕 둘뿐이다.
- 표 1행이나 1열을 좌측정렬하기. 긴 서술문 열만 예외다.
- 병렬 항목을 넷 이상 늘어놓기. 칸을 채우려고 항목 수를 맞춘 티가 난다.
- 큰 숫자를 카드처럼 나란히 세우기. 숫자에는 판단이나 단위 맥락이 붙어야 하고, 표 안이 제자리다.
- 아이콘을 단독으로 나열하기(아이콘 + 작은 글씨가 배경 없이 떠 있는 형태).
- 원형 배지에 문자 글리프(₩ ◆ ● ▲ ★) 넣기. 폰트 없는 PC에서 빈 원으로 보인다.
- 좌우 2단을 같은 폭으로 먼저 긋기. 내용 성격에 따라 비대칭으로 자른다.
- 여백 방치. 빈 공간은 행 높이·블록 간격으로 흡수한다.
- 한 열의 모든 셀을 bold 처리하기. 전부 굵으면 강조가 사라진다.
- 상자에 드롭섀도 걸기. 깊이는 선과 배경 명도 3단계(page/card/wash)로만 낸다.
- 수치가 들어가는 그림을 도형으로 그리기. 네이티브 차트를 쓴다(아래 6절).
- 대구식 수사("단순 A가 아니라 B", "A를 넘어 B")와 붙임표(—) 삽입구.
- 장표 문안에 서술형 어미(~했다·~이다). 개조식으로 명사형(~함·~임) 또는 체언 종결.
- 한 페이지에 도식 셋 이상 넣기.
- 제목 오른쪽에 기준일·출처·페이지를 적기. 그 줄은 제목만 쓴다.
- 정보량에 비해 도형을 부풀리기. 단계 이름과 숫자 하나뿐인 막대를 지면 절반 폭으로 키우면
  읽는 사람이 얻는 것 없이 자리만 차지한다.
- 구성비만 보여주고 총액 변화를 감추기. 총액이 움직였으면 금액 누적 막대를 쓴다.
- 표 셀이나 차트 막대까지 둥글게 하기. 모서리는 카드류 도형에만 적용된다.
- 모서리를 둥글게 해서 박스가 많은 문제를 덮으려 하기. 카드 수를 줄이는 것이 먼저다
  (`flow`의 `bare: true`, 병렬 항목 셋 상한, 2단 비대칭 분할).
- 워터폴 세로축이 0에서 시작하지 않는데 각주에 밝히지 않기.
- `heat` 격자에서 열마다 좋고 나쁨의 방향이 뒤집히게 두기. 열 이름을 같은 방향으로 맞춘다
  ("실행 난이도"가 아니라 "실행 용이성"). 진한 칸이 어떤 열에서는 우위, 어떤 열에서는 열위면 읽히지 않는다.
- 구성비를 원그래프로 그리기. `stackedBar`로 여러 해를 세로로 쌓으면 변화까지 보인다.
- 2×2 매트릭스를 축 표기 없이 그리기. `axis.y`와 `axis.yName`을 넣어 위아래 방향을 밝힌다.
- `build.sh`를 거치지 않고 `node`만 돌려서 나온 파일을 전달하기.
- 산출된 pptx를 파워포인트에서 직접 고치기. 다음 실행에서 사라지고 재검증도 안 된 상태가 된다.
- `pres.writeFile()`을 직접 불러 레이아웃 관문을 우회하기.
- 합계·계 행의 산출 방식을 각주에 안 밝히기. 단순평균인지 가중평균인지 재현이 안 되면
  회의에서 바로 걸린다.
- 반올림 때문에 합이 안 맞는 걸 말없이 조정하기. 어느 항목에 얼마를 걸었는지 각주에 적는다.
- 검증 없이 전달.
