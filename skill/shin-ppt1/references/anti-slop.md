# 안티슬롭 — 장표가 AI가 만든 티가 나는 지점

awesome-claude-design 레포는 Claude Design 출력물이 매번 똑같아 보이는 원인을
"기본 지문(default fingerprints)"으로 정리해 두었다. 그 표를 A4 보고 장표에 옮긴 것이다.

원리는 같다. 모델은 지시가 없으면 분포 한가운데로 수렴한다. 웹에서는 그게
틸 계열 강조색과 3단 그리드로 나타나고, 보고 장표에서는 아래 형태로 나타난다.

## 장표 기본 지문

| 지문 | 어떻게 생겼나 | 대응 규칙 |
|---|---|---|
| 큰 숫자 카드 3개 | 상단에 "42.1% / 1,240억 / 3.2배"가 테두리 상자로 나란히 | 숫자는 표 안이 제자리다. 단위와 판단이 붙지 않은 숫자는 읽는 사람이 해석할 수 없다 |
| 좌우 반반 2단 | 내용 성격과 무관하게 5.02 / 5.02로 자름 | 표는 좁게, 문장은 넓게. 비대칭으로 자른다 |
| 매 페이지 하단 시사점 행 | 페이지마다 색 박스에 "시사점:"이 붙음 | 결론은 상단 요약박스에서 한 번만. 하단 행 없음 |
| 병렬 4개 맞추기 | 항목이 셋인데 칸을 채우려고 넷째를 만들어 냄 | 셋을 넘기면 표로 옮긴다. 항목 수를 칸에 맞추지 않는다 |
| 아이콘 나열 | 아이콘 + 한 줄 글씨가 배경 없이 가로로 떠 있음 | 아이콘은 도식 카드나 테두리 블록 안에서만 |
| 그림자 카드 | 모든 상자에 옅은 드롭섀도 | 깊이는 선과 배경 명도 3단계로만 |
| 강조색 남발 | 세로바·강조 숫자·도식 테두리·막대가 전부 accent | accent는 페이지당 한 지점 |
| 하단 여백 방치 | 콘텐츠가 6.0에서 끝나고 1.8인치가 빔 | 하한(각주 1줄 7.79 / 2줄 7.64)까지 행 높이·도식 높이로 흡수. `checkLayout()`이 0.50 초과분을 잡아낸다 |
| 2단 높이 어긋남 | 좌단은 6.0에서 끝나는데 우단은 6.9까지 내려옴 | 좌우 하단 차이 0.40 이내. 짧은 쪽 도식·표를 키운다 |
| 도식 아래 빈 띠 | 설명이 한 줄인데 영역은 두 줄을 잡고 있음 | `timeline`의 `noteH` 등으로 실제 줄수에 맞춘다 |
| 정보량에 비해 부풀린 도형 | 단계 이름 하나와 숫자 하나뿐인 막대가 지면 절반 폭을 차지함 | 도형은 담는 정보량에 맞춰 줄이고, 설명·전환율을 옆에 두어 자리를 쓰게 함 |
| 총액을 감춘 구성비 | 100% 누적 막대만 놓아 총액이 늘어난 사실이 안 보임 | 총액이 움직였으면 금액 누적 막대. 100% 누적은 총액이 무의미할 때만 |
| 제목 줄이 두 덩어리 | 제목 왼쪽, 기준일·페이지 오른쪽으로 갈라져 시선이 두 번 감 | 제목만 남기고 나머지는 각주 줄로 내림 |
| 균일한 카드 격자 | 같은 크기 박스가 같은 간격으로 늘어섬. 모서리를 둥글게 해도 그대로임 | 카드 수를 줄이고 크기를 다르게. `flow`의 `bare: true`로 테두리를 뺌 |
| 파워포인트에서만 나는 오류 | LibreOffice 렌더는 멀쩡한데 파워포인트에서 복구 대화상자가 뜸 | `preflight.py --fix`를 산출 전에 무조건 통과시킴 |
| 고칠 수 없는 가짜 표·차트 | 도형 위에 텍스트를 얹어 만든 막대와 표. 숫자를 바꿔도 그림이 안 따라옴 | 표는 `addTable`, 수치 그림은 `chartBar`·`chartLine`·`chartStack100`·`chartWaterfall` |
| 웹 브랜드 색 직수입 | SaaS 팔레트의 보라·형광 시안이 보고서에 들어옴 | 금융권에서 쓰는 감청·청회·심청록·회청·황동·벽돌 계통으로 |
| 표 전 열 굵게 | 강조하려고 한 열 전체를 bold | 전부 굵으면 강조가 사라진다. 셀 단위로 찍는다 |
| 원형 배지 글리프 | 원 안에 ₩ ◆ ● ▲ ★ | 폰트 없는 PC에서 빈 원. 도형으로 그린 아이콘 10종을 쓴다 |
| 무지개 계열색 | 막대 계열색을 페이지마다 다르게 | `C.series` 순서 고정. 같은 계열은 자료 전체에서 같은 색 |
| 네이티브 차트 | pptxgenjs `addChart` 기본 스타일 그대로 | 도형으로 그린다. 기본 차트는 범례·눈금 스타일이 이 시스템과 맞지 않는다 |

## 문안 지문

레포의 안티슬롭 프롬프트가 시각 요소를 다루듯, 문안에도 같은 수렴 현상이 있다.

| 지문 | 예 | 대응 |
|---|---|---|
| 대구식 수사 | "단순 A가 아니라 B", "A를 넘어 B" | 결론(B)을 단정 평서문으로 바로 쓴다 |
| 붙임표 삽입구 | "핵심은 — 여기서 중요한 건 — 시점이다" | 문장을 나눈다 |
| 추상 명사 주어 | "시장이 말하고 있다", "위기가 다가온다" | 사실 서술로 바꾼다 |
| 격언형 마무리 | 제목과 끝문장을 수미상관으로 맞춤 | 제목은 내용 요약형 평범한 문구 |
| 군사·게임 은유 | 실탄, 창이 열렸다, 락인 | 실무 용어. 은유는 자료 전체에서 최대 1개 |
| 명령형 병렬 마무리 | "각 부서는 ~하라"가 줄줄이 | "~해 주기 바란다"로 풀고 문장 구조를 다르게 |
| 서술형 어미 | "~했다", "~이다" | 개조식. 명사형(~함·~임·~됨) 또는 체언 종결 |

## 산출 전 자체 점검

생성 스크립트를 다 쓰고 렌더하기 전에 다섯 개만 본다.

1. 이 페이지에 accent가 몇 군데 찍혔나. 둘 이상이면 하나로 줄인다
2. 큰 숫자가 표 밖에 떠 있나
3. 하단에 1인치 이상 비었나
4. 병렬 항목이 넷 이상인 블록이 있나
5. 문안에 대구식 수사나 서술형 어미가 있나

## 이 지문들이 생기는 이유

레포가 Anthropic 쿡북에서 인용한 문장이 원인을 그대로 설명한다.
모델은 분포 한가운데의 무난한 출력으로 수렴하고, 프론트엔드에서는 그것이
사용자들이 "AI 슬롭"이라 부르는 미감으로 나타난다.

보고 장표에서도 똑같다. 지시가 없으면 "큰 숫자 3개 + 반반 2단 + 하단 시사점 행"으로
간다. 그 형태 자체가 틀린 것은 아니고, 모든 자료가 그렇게 생겼다는 것이 문제다.
읽는 사람이 열 장을 받아 보면 열 장이 같은 골격이고, 그래서 아무것도 눈에 남지 않는다.

이 스킬의 골격 규칙(요약박스 두괄식 / 비대칭 2단 / 하단 행 없음 / accent 한 지점)은
전부 그 수렴을 한 칸씩 밀어내려고 있는 것이다.
