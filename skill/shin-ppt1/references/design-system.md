# shin-ppt1 디자인 시스템

awesome-claude-design 레포의 `DESIGN.md` 문서들은 9개 섹션으로 되어 있다. 그 구성을
그대로 따랐다. 웹용 문서라 반응형·호버 항목은 A4 지면에 맞는 항목으로 바꿨다.

팔레트는 이 문서에 없다. `themes.md`에 있다. 여기 적힌 것은 **테마가 바뀌어도 변하지
않는 것들**이다.

## 1. 지면의 성격

리서치 리포트다. 정보 밀도가 높고, 색으로 개성을 내지 않고, 읽는 사람이 한 장에서
판단을 끝낼 수 있게 만든다. 구조는 선·여백·타이포 위계로 낸다.

작성 주체가 특정 부서로 읽히지 않아야 하는 보고에 쓴다. 그래서 부서 색·부서명·로고를
넣지 않는다.

**제목 오른쪽에는 아무것도 넣지 않는다.** 기준일, 출처, 페이지, 작성부서 전부
제목 옆이 아니라 각주 줄로 내린다. 제목 줄에 두 덩어리가 놓이면 시선이 갈라지고,
그 자리에 넣는 정보는 대개 본문을 읽고 난 뒤에 확인하는 것들이다.

## 2. 색의 역할

역할 키 13개로 고정한다. 테마가 값을 갈아끼울 뿐 키는 늘어나지 않는다.

| 키 | 용도 |
|---|---|
| page | 지면 배경 |
| card | 표·도식 카드 배경(page와 다를 수 있다) |
| ink | 제목, 표 헤더 글씨, 굵은 마감선, 합계 |
| body | 일반 본문, 표 본문 |
| mute | 보조 설명, 캡션, 각주, 눈썹 라벨 |
| rule | 얇은 선, 표 행 구분, 비강조 막대·테두리 |
| accent | 강조 1지점. 세로바·불릿 마커·강조 숫자·도식 강조 테두리 |
| accentLt | 어두운 배경 위에서만 쓰는 강조 런 |
| wash | 아주 옅은 배경(표 강조 열, 도식 강조 카드) |
| dark | 상단 요약박스 배경 |
| onDark | dark 위 글자색 |
| sky | 본문 중 강조 메시지 박스 배경 |
| msgInk | sky 위 글자색 |

여기에 `series` 6색이 붙는다. 다계열 막대 전용이고 순서를 고정한다.

**accent는 한 페이지에 한 지점만 찍는다.** 세로바·강조 숫자·도식 테두리를 전부 accent로
칠하면 강조가 사라진다. 밝은 배경의 강조는 accent 굵은 글씨로 처리하고 배경을 칠하지 않는다.

## 3. 타이포

- **A4 가로**: `pres.defineLayout({name:"A4L", width:11.6929, height:8.2677})`
- 여백: 좌우 0.65in → 콘텐츠 폭 CW = 10.39in
- **글꼴은 두 벌뿐이다.** 페이지 제목과 상단 요약박스가 HY헤드라인M,
  **나머지 전부가 맑은 고딕**이다. 셋째 글꼴을 들이지 않는다
- 등폭 글꼴(Consolas 등)을 숫자 열에 쓰지 않는다. `tnum` 옵션은 오류를 낸다.
  자릿수를 맞추고 싶으면 소수 자리를 통일하고 열 폭을 같게 잡는다

**크기는 코드의 `TS` 객체 한 곳에서만 정한다.** 호출부에서 `fontSize`를 숫자로 쓰지 않는다.
쓰는 순간 그 자리만 위계가 어긋나고, 나중에 스케일을 조정할 때 그 자리만 남는다.

| 키 | 크기 | 쓰는 곳 |
|---|---|---|
| `TS.title` | 19pt | 페이지 제목 (HY헤드라인M) |
| `TS.summary` | 15pt | 상단 요약박스 |
| `TS.bigValue` | 22pt | 분기 도식 머리의 대표 숫자 |
| `TS.cardTitle` | 14pt | 도식 카드 제목, 비교 헤더 |
| `TS.sub` | 13.5pt | 소제목 |
| `TS.layer` | 13pt | 적층·계층·단계 라벨 |
| **`TS.table`** | **12.5pt** | **표 본문 기본** |
| `TS.cardBody` | 12pt | 도식 카드 설명, 강조 메시지 박스 |
| `TS.bullet` | 12pt | 불릿 본문 |
| `TS.gridHead` | 12pt | 격자·레인·간트 열 머리 |
| `TS.gridCell` | 11.5pt | 격자·레인 칸 |
| `TS.tableMin` | 11.5pt | 표 본문 하한. 이 아래로 내리지 않는다 |
| `TS.subDesc` | 11pt | 소제목 옆 보조 설명, 우측 기준일 |
| `TS.axis` | 11pt | 축 라벨, 눈금 이름 |
| `TS.legend` | 10.5pt | 범례, 캡션 |
| `TS.value` | 10pt | 막대·꺾은선 위 수치 |
| `TS.foot` | 9pt | 각주 |

### 위계에서 지킬 것

- **소제목(13.5)은 표 본문(12.5)보다 크다.** 이게 뒤집히면 페이지가 평평해 보인다
- 각주(9)를 빼면 어떤 글씨도 10pt 아래로 내려가지 않는다
- 표가 좁아 줄바꿈이 나면 `TS.tableMin`(11.5)까지만 내리고, 그 아래로는 열 구성을 바꾼다

### 블록을 키웠으면 글씨도 키운다

**"작아 보인다"는 지적의 실제 원인은 글씨 크기가 아니라 글씨와 블록의 비율이다.**
표를 키워놓고 글씨를 그대로 두면 셀 안이 비어 보이고, 그게 작아 보인다는 인상을 만든다.

표 행 높이 하한 = `글씨(pt) ÷ 24 + 0.20`.

| 글씨 | 행 높이 하한 | 한 줄만 들어갈 때 |
|---|---|---|
| 12.5pt | 0.72 | 0.60 |
| 11.5pt | 0.68 | 0.56 |

`rowH`는 최소값일 뿐이고 PowerPoint가 더 키우므로, 표 아래 요소는
`표 top + Σ rowH + 0.10` 이후에 배치한다.

도식도 같다. 각 헬퍼의 기본 높이(`stack`의 `lh` 0.58, `compare`의 `rh` 0.62,
`heat`의 `rh` 0.60, `gantt`의 `rh` 0.58, `swimlane`의 `rh` 0.74)는 이 스케일에 맞춰
잡은 값이다. 공간이 남는다고 높이만 키우면 다시 같은 문제가 생긴다.

## 4. 컴포넌트

- **addSlide(pres)** — 지면색을 깐 슬라이드. `pres.addSlide()`를 직접 쓰지 않는다
- **eyebrow(s, text)** — 제목 위 분류 표기. 부서명은 넣지 않는다
- **header(s, title, {eyebrow})** — 제목 + 굵은 마감선. 제목이 전폭을 쓴다
- **summary(s, l1, l2)** — 상단 요약박스. 한 줄 36자 이내로 끊는다. l2는 accentLt 강조 줄.
  `darkPage` 테마에서는 accent 테두리가 자동으로 붙는다
- **sub(s, x, y, label, desc, descW)** — accent 세로바 + 소제목 + 우측 보조 설명.
  단위 표기는 여기 넣는다(제목 옆이 아니다)
- **openTable(s, rows, {x,y,w,colW,rowH,washCols,cardBg,margin})** — 오픈 테이블.
  위 굵은 선 / 헤더 아래 얇은 선 / 행 구분선 / 아래 굵은 선.
  **colW 합계 == w 필수.** 반환값은 표 하단 y
- **makeTableStyles(fs, {numAlign})** — 셀 스타일. 기본 12.5pt.

  **정렬 규칙**
  - **1행(머리글)과 1열은 중앙정렬이 기본이다.** 예외 없다
  - 숫자 열, 짧은 값 열도 중앙정렬(`td`·`num`·`tot`)
  - 셀 안에서 줄바꿈되는 **긴 서술문 열만** `tdL`(좌측). 그 열도 머리글은 중앙
  - 자릿수가 세 자리 이상 벌어져 크기 비교가 어려운 표에 한해 `numAlign: "right"`
- **bullets(s, items, x, y, w, fs, step)** — accent 작은 사각 마커.
  **"⇒" 결론 줄에는 마커를 붙이지 않는다**
- **msgBox(s, y, h, text)** — 강조 메시지. 페이지당 한 개 이내
- **bars / barsGroup** — 세로 막대. 뒤 밴드 없음.
  `bars`는 단일 계열(강조 항목만 accent), `barsGroup`은 다계열(`C.series` 순서 고정)
- **fmtNum(v, 자릿수) / textOn(헥사)** — 천단위 구분, 배경 명도에 맞는 글자색 선택

### 도식 15종

구조·관계는 `flow` `stack` `branch` `tree` `swimlane` `funnel`,
판단·비교는 `matrix` `compare` `heat`,
수치는 `bars` `barsGroup` `waterfall` `lineTrend` `stackedBar`,
일정은 `timeline` `gantt` `chevron`이다. 목적별 선택표는 SKILL.md 5절에 있다.

확장 도식에서 주의할 점만 적는다.

- **waterfall** — 세로축이 0에서 시작하지 않는다. 0에서 시작하면 기준 막대가 화면을 다
  먹고 증감 막대가 보이지 않는다. 바닥은 최저 수준 아래로 자동으로 잡히며,
  **축이 0이 아니라는 사실을 각주에 밝힌다.** 증가는 청회, 감소는 회청, 기준·합계는 ink다.
  초록·빨강을 쓰지 않으므로 방향은 부호와 막대 위치로 읽는다
- **lineTrend** — 계열 4개까지. 기본 세로축은 0에서 시작하고 `vmin`으로 바꿀 수 있다.
  수치 표기는 첫 계열에만 붙는다(`values: true`로 전체 표기)
- **stackedBar / chartStack100** — 100% 누적은 총액을 감춘다. 총액이 움직였으면
  `chartBar`에 `barGrouping: "stacked"`를 걸어 **금액 누적**으로 그리고, 비중은 표로 따로 읽힌다.
  100% 누적은 총액이 무의미하거나 본문에서 이미 밝힌 경우에만 쓴다.
  `parts` 순서는 전 행에서 같아야 한다
- **heat** — 값은 0~3. **열마다 좋고 나쁨의 방향을 같게 맞춘다.** 진한 칸이 어떤 열에서는
  우위이고 어떤 열에서는 열위면 격자 전체가 읽히지 않는다
- **matrix** — `axis = { x:[왼쪽말, 오른쪽말], xName, y:[아래말, 위말], yName }`.
  `y`를 주면 왼쪽에 0.58in 여백을 내고 방향을 말로 적으며 축 이름을 세워 넣는다.
  **축 방향을 안 밝히면 어느 칸이 좋은 칸인지 읽는 사람이 알 수 없다**
- **gantt** — `from`·`to`는 기간 인덱스이고 양끝을 포함한다. 분기 단위로 잡았으면
  한 달짜리 일정도 분기 전체 폭으로 그려진다. 월 단위가 필요하면 `periods`를 월로 준다
- **swimlane** — 같은 레인에서 이웃한 칸끼리만 화살표가 붙는다. 빈 칸은 `null`
- **funnel** — 첫 단계가 폭 기준이다. 전 단계 대비 전환율은 자동으로 계산된다.
  `zoneW`로 막대 영역을 좁혀야 한다. 기본값(폭의 52%)은 단계가 많을 때 기준이고,
  4단계 이하에서는 34% 안팎이 적당하다. 색면을 줄이고 설명이 자리를 갖게 한다
- **caption / footer** — 캡션·각주는 mute. `footer(s, notes, { page: "3 / 10" })`로
  각주 줄 오른쪽 끝에 페이지를 붙인다. 기준일·출처도 각주 항목으로 적는다

## 5. 페이지 골격과 세로 리듬

```
0.24  눈썹 라벨 (선택)
0.46  제목 — 지면 폭을 다 쓴다. 오른쪽에 아무것도 두지 않는다
0.90  굵은 마감선
1.06  상단 요약박스 (h 0.66) — 하고 싶은 말을 두괄식으로
2.00  소제목 ①
2.44  콘텐츠
...   (필요할 때만) 메시지 박스
      각주 마감선 + 각주 — footer()가 바닥 기준으로 자동 배치
```

**여백은 눈대중으로 맞추지 않는다.** 아래 다섯 값이 전부다. 중간값을 만들어 쓰지 않는다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `BAND_TOP` | 2.00 | 콘텐츠가 시작하는 y(첫 소제목) |
| `SUB_GAP` | 0.44 | 소제목 y → 그 아래 콘텐츠 y |
| `BLOCK_GAP` | 0.34 | 블록 하단 → 다음 소제목 y. 0.30~0.46 사이 |
| `COL_TOL` | 0.40 | 2단 좌·우 마지막 요소 하단 차이 허용치 |
| `SLACK_MAX` | 0.50 | 이보다 더 비면 흡수 대상 |

콘텐츠 하한은 각주 줄수로 정해진다. `bandBottom(줄수)` = `8.14 - 0.14 × 줄수 - 0.20`.

| 각주 | 하한 |
|---|---|
| 1줄 | 7.79 |
| 2줄 | 7.64 |
| 3줄 | 7.49 |

### 여백이 남을 때 흡수하는 순서

빈 자리에 항목을 새로 만들어 넣지 않는다. 아래 순서로 기존 요소를 키운다.

1. **표 행 높이** — `rowH`를 균등하게 올린다. 셀이 비어 보이면 글씨도 12pt로 올린다
2. **도식 높이** — `flow`의 `h`, `stack`의 `lh`, `matrix`의 `h`, `barsGroup`의 `maxH`
3. **블록 간격** — `BLOCK_GAP`을 0.34에서 0.46까지 벌린다
4. 그래도 0.5in 넘게 남으면 그 페이지에 들어갈 내용이 부족한 것이다. 옆 페이지와 합친다

### 짧은 설명이 만드는 빈 띠

도식 중 설명 영역 높이가 고정된 것들이 있다. 설명이 한 줄인데 높이는 두 줄을 잡고 있으면
도식 아래에 빈 띠가 생기고, 이게 "여백이 엉망"으로 보이는 가장 흔한 원인이다.
`timeline`은 `noteH`로 조절한다(기본 0.86, 한 줄이면 0.62).

### 검사

페이지를 다 짠 뒤 `checkLayout()`을 부른다. 어기면 빌드 중 콘솔에 경고가 뜬다.

```js
tpl.checkLayout("3p paper", { cols: [좌단하단y, 우단하단y], tail: msgBox하단y, footLines: 2 });
```

세 가지를 본다. ① 하한 초과 ② 2단 좌우 하단 차이 ③ 잔여 여백 과다.

## 6. 깊이

**그림자를 쓰지 않는다.** 깊이는 세 가지로만 낸다.

1. 배경 명도 3단계 — `page` → `card` → `wash`
2. 테두리 두께 — 비강조 0.75pt, 강조 1.25pt
3. 선의 굵기 — 마감선 0.028in, 행 구분선 0.008in

`paper`처럼 지면이 흰색이 아닌 테마에서는 표에 `cardBg: true`를 켠다. 종이 위에 카드가
놓인 것처럼 읽힌다. `page`가 흰색인 테마에서는 켜도 차이가 없다.

### 모서리

`useCorners()`로 덱 단위에서 한 번만 정한다. 기본은 `soft`다.

| 값 | 반경 | 쓰는 곳 |
|---|---|---|
| `square` | 0 | 대외 제출, 심의·감사 자료 |
| `soft` | 0.05in | 기본. 인쇄물에서 겨우 눈에 띄는 정도 |
| `round` | 0.10in | 화면 배포, 사내 공유 |

**카드류 도형에만 적용된다.** 표, 마감선, 강조 열 배경, 차트 막대는 어느 값에서도
각진 채로 둔다. 표의 셀까지 둥글게 하면 보고서가 아니라 앱 화면으로 읽힌다.

높이가 작은 도형에 큰 반경이 들어가면 알약처럼 보이므로 `box()`가 짧은 변의 22%로 제한한다.

### 박스 개수가 모서리보다 중요하다

"AI가 만든 것 같다"는 인상의 실제 원인은 모서리가 각졌다는 것이 아니라
**같은 크기의 박스가 균등한 간격으로 늘어서 있다**는 데 있다. 모서리만 둥글게 하면
균일한 각진 카드가 균일한 둥근 카드로 바뀔 뿐이다.

박스를 줄이는 방법이 먼저다.

1. 카드 개수를 줄인다. 병렬 항목 셋이 상한이고, 넷이면 표로 옮긴다
2. 카드 크기를 다르게 잡는다. 좌우 2단을 같은 폭으로 자르지 않는다
3. 테두리를 뺀다. `flow`의 `bare: true`는 테두리 대신 상단 선만 남긴다.
   강조 단계만 옅은 배경으로 표시한다
4. 관계가 단순하면 도식을 쓰지 않는다. 세 항목의 순서는 문장 한 줄로도 전달된다

## 7. 지켜야 할 것과 하지 말 것

지켜야 할 것

- 결론을 상단 요약박스에서 한 번만 말한다
- 2단은 내용 성격에 따라 비대칭으로 자른다
- 병렬 항목은 셋까지. 넷 이상이면 표
- 항목의 해석은 별도 불릿이 아니라 표 안 열로
- 남는 세로 공간은 행 높이와 블록 간격으로 흡수
- 숫자에는 단위와 판단이 붙는다

하지 말 것은 `anti-slop.md`에 표로 정리돼 있다. 산출 전에 그 문서의 자체 점검 5항목을
먼저 본다.

## 8. 출력 매체

이 시스템은 A4 가로 한 장을 전제로 한다. 매체가 바뀌면 테마를 바꾸지 골격을 바꾸지 않는다.

| 매체 | 테마 | 확인 사항 |
|---|---|---|
| A4 인쇄, 컬러 | report / paper / dense | 배경 면적이 넓지 않은지 |
| A4 인쇄, 흑백 | mono | accent가 ink와 같아 흑백에서도 위계가 유지됨 |
| 회의실 스크린 | report / mono | 흰 지면으로 투사한다. 어두운 지면 테마는 두지 않는다 |
| PDF 배포 | 아무 테마 | 폰트 임베딩 없이 렌더되므로 HY헤드라인M은 제목에만 |

## 9. 생성 스크립트 규약

```js
const tpl = require("./template.js");
const pres = tpl.newPres(require("pptxgenjs"), "report");
const { C, MX, CW, RX, COLW } = tpl;

tpl.useTheme("report");            // 페이지마다 명시(견본용). 실제 보고서는 덱 단위 1회
const s = tpl.addSlide(pres);      // pres.addSlide() 직접 호출 금지
tpl.header(s, "제목", "기준일");
tpl.summary(s, "결론 첫 줄", "보조 줄");
const st = tpl.makeTableStyles();                     // 테마 전환 이후에 생성
```

- 색 값을 직접 쓰지 않는다. 헥사코드를 쓰는 순간 그 페이지만 테마 전환이 안 된다
- `makeTableStyles`는 호출 시점의 테마 색을 굽는다. 테마를 바꿨으면 다시 생성한다
- 수정은 생성 스크립트를 패치 후 재생성한다. 산출된 pptx를 직접 고치지 않는다
- 생성 직후 `python3 preflight.py <파일.pptx> --fix`를 돌린다. 파워포인트가 거부하는
  구조 오류 14가지를 검사하고, 도형 ID 중복은 자동으로 해소한다.
  종료코드가 0이 아니면 그 파일은 전달하지 않는다
